## Production and rollback

These commands are for a future release operator using Bash, the authenticated Netlify CLI and Node.js. They publish the exact checked draft or restore the exact base by ID. Load this function in the shell first.

```bash
site='1143f7cd-ffc0-41f5-b8cd-7501dd78ba52'
publish_if_live() {
  local expected="$1" target="$2" actual
  actual=$(set -o pipefail; netlify api getSite --data "{\"site_id\":\"$site\"}" | node -p "JSON.parse(require('node:fs').readFileSync(0, 'utf8')).published_deploy.id") || return 1
  if [[ "$actual" != "$expected" ]]; then
    printf 'STOP. Expected %s. Current live deploy is %s.\n' "$expected" "$actual" >&2
    return 1
  fi
  netlify api restoreSiteDeploy --data "{\"site_id\":\"$site\",\"deploy_id\":\"$target\"}" >/dev/null
}
```

To publish the verified draft, run

```bash
publish_if_live '6afb3b6479ad940cae30abbe' '6afb52cb1342cf73a7320f04'
```

To roll back after that publication, run

```bash
publish_if_live '6afb52cb1342cf73a7320f04' '6afb3b6479ad940cae30abbe'
```

Both operations check the currently published ID immediately before requesting the change. A simulated Netlify API confirmed that the guard stops on a changed ID and selects the intended target for both publication and rollback. The check and publish request are separate API calls.

Alpha also builds production on a push to `master` or `main`. The commands above act on the verified Netlify deploy IDs and make no Git push.
